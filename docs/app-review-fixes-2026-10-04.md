# app 层评审整改记录

本轮落实 R1～R14。R1 按产品要求调整为**关断有固定超时，超时停止重试且允许休眠**，
同时保留未确认/可能开启的输出信息。总期限沿用 connect_ms，默认 10 秒，不新增持久化键。

| 项目 | 最终行为 | 回归套件 |
|---|---|---|
| R1 | 超时前 UNKNOWN/OFF 待办阻止休眠；超时置 stop_timed_out，取消发送并停止无线；不伪造 OFF | remote、power |
| R2 | 遥测回调只发邮箱；未确认 ON 保守锁存，旧 OFF 不能清除，输出遥测必须匹配当前请求 | remote |
| R3 | ISR/任务取消旧发送代际，旧 FIFO/在途重传取消，新 OFF 等驱动完成；射频重启清除旧发送所有权 | transport、remote |
| R4 | 常驻采样任务、固定请求池与引用；通知和不可变结果属于同一请求，同步读取绑定自身请求 | battery |
| R5 | 关采样入口、等待 GPIO/回调完成；显示任务关闭确认后才隔离 GPIO；所有拒绝分支恢复服务 | battery、power、ui |
| R6 | NVS 持久化与原子缓存发布串行，读者仍无锁；always_on 使用同一写事务保护 | settings |
| R7 | 保存失败不报告成功，发布 last_error；最多三次完整窗口尝试 | battery |
| R8 | reset、USB 边沿及倍率变更推进代际，局部窗口重建，旧保存事务拒绝提交 | battery |
| R9 | 新鲜保护清除后恢复 OFF/ON；不能用保护拒绝之前的旧遥测立即清除本轮拒绝 | remote |
| R10 | 低电消息到期退出；倒计时优先普通菜单/消息，紧急控制仍优先 | ui |
| R11 | OLED 独立所有者与最新帧邮箱；失败截止时间退避、限频日志、连续三次失败重建总线 | ui |
| R12 | 急停/接收日志固定队列零等待提交，低优先级输出；Shell 优先级降为 2，丢弃计数可查 | diagnostics |
| R13 | ON 入队成功才消费意图；入队失败在期限内重试，STOP 作废；ON 应答超时转为 OFF | remote |
| R14 | 固定写序号/擦除代际快照，同一事务读取头与文本；被覆盖时明确中止导出 | export |

额外整理：轻量 app_types 消除 UI 对无线协议/电源执行组件的公开依赖；热路径运行参数
改为 Id；收紧私有 CMake 依赖；菜单使用显式动作映射；按键初始化返回错误，队列丢弃
计数可查询；重绘标志始终消费；README 与异步显示、Shell 注册和静置策略一致。

## 验证

- 主机编译实际源文件，8 个套件共 27 组场景通过。入口：
  [tests/app_regression/run.py](../tests/app_regression/run.py)。
- 完整 ESP-IDF v6.0 ESP32-C3 构建与固件布局校验在隔离目录执行。测试依赖使用 manifest
  固定提交的公共组件及工程内三项补丁，Component Manager 解析确认覆盖来源为本地目录。
- APP 为 996432 字节，1 MiB 应用分区剩余 52144 字节；合并镜像为 1061968 字节，
  APP 偏移及空白 NVS 区间校验通过。隔离构建禁用依赖下载，使用上述固定依赖。
- 提交前启用官方 Component Manager，重新解析并下载固定提交的依赖，生成锁文件；
  实际下载源码与此前测试的固定源码一致，完整构建及固件布局校验再次通过。
- 构建不会修改已有项目 build/固件或手工改写 managed_components/dependencies.lock。
- 2026-10-04：用户已烧录到硬件，并确认验证成功。

主机替身验证的是应用状态与指定交错，不能给出空口延迟、真实 I2C/ADC 行为、任务栈余量
或深睡电流。板上应重测无线丢包/排队、USB 不读、OLED 故障/恢复、USB 快速拔插、低电、
关断期限及深睡中止恢复。已交给射频的 ON 无法撤回；新 OFF 必须处理这种在途帧。

新增常驻 ADC/OLED/诊断任务有固定 RAM 成本；回归时记录最小空闲堆、最大空闲块和各任务
栈余量。逻辑回归通过不等同于已完成硬件性能验收。
