# app_diagnostics

急停热路径的异步日志出口。`init()` 必须先于 `EmergencyRemote::init()`；初始化失败由
主入口明确处理。产品事件/W/E 使用 32 项队列，普通 INFO 使用独立 16 项队列；
消费者优先输出事件，普通诊断积压不会耗尽事件队列。队列空时等待任务通知，没有周期轮询。
调用方格式化后零等待入队，队满或未初始化时丢弃并计数。tag 必须具有静态生命周期，
接口不能从 ISR 调用。

唯一消费者优先级为 1，栈 3072 字节，通过 ESP 日志出口输出，因此保持已有的
`ProductEvent` 黑匣子白名单策略。控制任务不等待 USB/stdout 或 Flash 捕获。
`dropped()` 暴露丢弃次数，`flush(timeout)` 等待已接受记录排空（包括等待期间的新提交），默认 200 ms。
flush 超时不会销毁队列、信号量或后台仍在使用的对象。

休眠和 Shell 导出先 flush 本组件再 sync 黑匣子。队列有界意味着极端日志压力下允许
丢诊断记录，控制功能仍继续；使用 `blackbox status` 检查 `async_log_dropped`。

## 两类日志的约定

- 实时诊断使用普通组件标签的 INFO，可按周期输出；`AppRuntime` 每秒记录运行状态，
  每十秒记录资源余量。该标签不在黑匣子 INFO 白名单内。
- 操作/结果/状态变化使用 `APP_LOGI("ProductEvent", ...)`。消费时自动补充
  `e`（事件入队序号）、`t`（事件发生/入队时的运行毫秒）。
  这些字段位于正文，避免依赖 Flash 追加时刻还原事件时间。
- ProductEvent 正文最多 127 字符，为元信息与黑匣子标签留出空间；普通日志最多 191 字符。
  截断以 `[cut]` 显式标记。排空后输出丢弃/截断汇总；普通诊断缺口为 INFO，关键事件缺口为 WARN。
- `ErrorLog` 由单一任务持有：首次失败及原因变化记录 ERROR，重复失败为普通 INFO，
  恢复记录 ProductEvent。不要在周期统计处使用 W/E；一次实际操作的拒绝或保存失败可以记录事件。
- 保持公共组件的 W/E + 白名单 INFO 捕获策略；不放行底层组件整个 INFO 标签。
  应用层在变化处补记保存节点、信道、保护原因与控制结果。
  本工程无线副本的配对保存结果使用专用 `PairingEvent` 标签，白名单只增加这个事件标签。
  它保留 MAC、角色、信道、实际 NVS 保存结果及发生时刻，避免同一节点重新配对被快照去重漏掉。

## 现场还原

以 `t` 的单调性划分开机段（重启后运行时间归零，`t` 会下降），用 `e` 判断同一开机内的事件顺序；
开启/关闭记录另外携带 `op`。
一次操作的多个无线请求 ID 和重试共享 `op`，结束记录包含次数、耗时及结果。
`confirmed` 才表示已收到匹配的成功应答；`unconfirmed_timeout` 表示关断总期限耗尽，
停止重试并按产品策略允许休眠，不能作为已经关闭的证据。

固定队列、公共捕获环与 Flash 队列仍有容量和错误边界，断电可能丢失末尾尚未持久化的记录。
`flush()` 只确认 ESP 日志出口已处理，必须再 `BlackboxService::sync()` 才等待存储。
Shell 交互模式关闭 ESP 日志时仍可能漏记；本次按约定保留该行为，没有修改公共 Shell 或捕获模块。
